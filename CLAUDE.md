# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A collection of custom indicators for the [Tradovate custom-indicator API](https://tradovate.github.io/custom-indicators/). Each file in `indicators/` is a **self-contained JavaScript module** that gets pasted, as-is, into Tradovate's in-platform Code Explorer (Chart → Indicators → code editor). There is no build step, no bundler, no `package.json`, and no local dependencies — the `require("./tools/...")` calls resolve against Tradovate's own bundled SDK at runtime inside the platform.

Because of this, **do not add npm dependencies or split an indicator across multiple local files.** Each indicator must remain one paste-able module. `require("lodash")` is available inside the platform if needed.

## Testing / verifying changes

There is no test runner in the repo. Indicators are validated by pasting into Tradovate and adding them to a chart. Logic-only changes (ATR math, VWAP, time/session handling) can be checked with a throwaway local Node harness that **stubs the `./tools/*` modules** (`predef`, `meta`, `EMA`, `graphics`) and feeds synthetic bars — put such harnesses in the scratchpad, not in the repo. Do not commit stubs or a `tools/` directory: those names must resolve to Tradovate's bundled modules, not local ones.

Make the `predef` stub **strict** — expose only the helpers known to exist (`paramSpecs.period/number/percent`, `styles.plot`, `plotters.*`) and throw on anything else. An indicator that calls a helper the real `predef` lacks throws during module load, so Tradovate never registers it and it just **doesn't appear in the indicator dropdown** — there is no error message on the chart. A lenient stub hides exactly this class of bug.

## Module contract (the shape every indicator must follow)

`module.exports` is an object; the important keys:

- `name`, `description` — identity shown in Tradovate.
- `calculator` — a class with `init()` (allocate/reset per-series state) and `map(d, index, history)` (called **once per closed bar**, in order). `map` returns either a number or an object whose keys match `plots`; the returned object may also carry `graphics`, `style`, `candlestick`.
- `params` — read at runtime as `this.props.<paramName>`. Only `predef.paramSpecs.period`, `.number` and `.percent` are confirmed to exist in the bundled `predef`; `paramSpecs` is **not** part of the documented API, so for anything else use the documented literal shape instead: `{ type: "number" | "boolean" | "enum" | "text", def, restrictions }`. A missing `paramSpecs` helper throws while the module is loading, so the indicator never registers and **silently disappears from Tradovate's dropdown** with no error on the chart — see the boolean params in `sessionRangeLevels.js`.
- `plots` — declares the named output series. `map`'s return object populates these by key.
- `plotter` / `plotters` — how plots are drawn: `predef.plotters.columns(field)`, `dots(field)`, `line`, `histogram`, etc. Can be an **array** of plotter definitions.
- `schemeStyles: { dark: {...}, light: {...} }` — per-plot color/width; supply both schemes.
- Optional: `inputType` (`meta.InputType.BARS`), `areaChoice` (`meta.AreaChoice.NEW` for its own pane vs `OVERLAY`), `tags`, `validate`.

### Bar accessors (`d`) worth knowing
`d.open/high/low/close/volume()`, `d.timestamp()` (a Date), `d.tradeDate()` (changes at each session boundary — use it to reset session accumulators), `d.isLast()`, `d.index()` (fine as a drawing x for `du()`, but do **not** use it to key per-bar state — `signal.js` v6 stored states by `d.index()` and in Tradovate no bar could find its predecessor; key state by `map()`'s `index` argument instead), `d.profile()` (volume-profile levels). `d.offerVolume()/d.bidVolume()` give **real** per-bar bid/ask delta when the feed provides it. `history.prior()/last()/first()/back(n)` reach earlier bars.

## Cross-cutting patterns established here

These conventions are shared across the existing indicators — follow them for consistency:

- **Fixed HUD overlay:** to pin an on-screen readout to the pane, return `graphics: { items: [...] }` from `map`, gate it on `d.isLast()` so only the latest bar draws it, and mark each item `global: true` with `origin: { cs: "frame", h: "left", v: "top" }`. Coordinates use helpers from `./tools/graphics` — `px(v)` (pixels), `du(v)` (domain/price units), `op(a, '-', b)`. `Shapes` primitives (`Rectangle`, etc.) position by their **center** and take one `fillStyle` per group; `Text` items take `point`, `text`, `style`, `textAlignment`. See `scalpProMeter.js`'s `hud()`.
- **Session VWAP:** accumulate `volume * typicalPrice` (prefer `d.profile()` levels when present) and reset the accumulators whenever `d.tradeDate()` changes. See `scalpProMeter.js`'s `vwap()`.
- **Self-contained indicators / ET session handling:** avoid `Intl` for timezones (not reliably available). Every session-aware indicator here computes the US Eastern offset with the same hand-rolled DST rules (2nd Sunday of March → 1st Sunday of November) and derives `minutes` and a `dayKey` from the bar timestamp to detect sessions — see `marketMagnet.js`/`sessionRangeLevels.js` (re-anchoring at each new session) and `sessionCountdown.js` (UK/Tokyo offsets too). `atrLevels.js` is deliberately session-agnostic. Reuse that approach rather than pulling in a date library.
- **Inline TA math over `tools/`:** when a `tools/` module's signature is uncertain, compute the indicator inline (e.g. `atrLevels.js` implements Wilder-smoothed ATR itself, with a warm-up simple-average phase) so the module stays portable. `EMA` is the one commonly required helper (`const EMA = require("./tools/EMA"); this.e = EMA(period); this.e(value)`).
- **Top-of-file config block + doc comment:** each indicator opens with a block comment explaining behavior and limitations, and tunable constants live in a clearly marked `CONFIG` section near the top.
- **Every indicator is tagged `tags: ["Custom Indicators"]`** — `tags` is what groups indicators in Tradovate's UI dropdown, so this single shared tag puts them all under one "Custom Indicators" folder. Use exactly this one tag on new indicators; do **not** add `predef.tags.*` alongside it, or the indicator will also appear under those built-in groups.
- **`name` matches the filename** (without `.js`) and is the unique identifier; `description` is the human-readable text Tradovate shows in the UI.
- **Text labels render to one side of their `point`, not centred on it.** `textAlignment` names say where the *text* sits relative to the anchor: `"rightMiddle"` draws it to the **right** of `point`, `"leftMiddle"` to the **left**, `"centerMiddle"` centred. Labels meant to sit right of a bar or inset from the pane's left edge must use `"rightMiddle"` — `"leftMiddle"` pushes them off-screen and only their tails survive. Valid values: `none`, `center|left|right` × `Above|Middle|Below`.
- **Assign `graphics` on EVERY bar, and mark single-render items `global: true`.** Two separate causes of the same symptom — a label repeating across the chart instead of appearing once:
  1. Omitting the `graphics` key on non-last bars leaves each bar holding whatever it last rendered, so every bar that was ever the last bar keeps its own cached copy. Since labels are anchored at `du(d.index())`, the stale copies sit at their own x and smear across the chart. Always assign it: `graphics: d.isLast() && { items: [...] }` is the documented idiom (`false` = "nothing here"). This includes early `return {}` paths — return `{ graphics: false }` instead.
  2. `global: true` marks an item **single render** (drawn once for the series, not once per bar). Any label meant to appear only at the last bar needs it. A frame-anchored HUD hides this bug, because repeated copies land on the same pixels; a bar-anchored label does not.
- **HUD text must be plain ASCII.** Tradovate's HUD font silently drops glyphs like `▲ ▼ –` — in `signal.js` a `"LAST  –"` row rendered as a bare "LAST" and read as broken. Spell states out (`BULL`, `none`).
- **Do not nest frame-anchored graphics in a `Container`.** Items marked `global: true` with an `origin: { cs: "frame", ... }` stop rendering entirely once they are children of a `Container`, even though the API documents `Container` as a plain grouping wrapper. Tried and reverted in `scalpProMeter.js`: wrapping the HUD to apply a `ZIndex` transform made the whole HUD vanish. Plot output can paint over `graphics` items and there is **no known way to force a frame-anchored overlay in front** — work around it instead (reserve space in the `scaler`, or draw a filled backdrop behind the text).
- **Horizontal lines that must move with the current candle belong in `graphics`, not `plots`.** A plot stores one value per bar, so a level anchored to the newest bar's open renders as a staircase across history. Use `{ tag: "LineSegments", lines: [{ tag: "Line", a: { x: du(i), y: du(price) }, b: { x: du(i + 1), y: du(price) }, infiniteStart: true, infiniteEnd: true }], lineStyle: { lineWidth, color, lineStyle? }, global: true }` — `infiniteStart/infiniteEnd` extend the segment forever along X, which is the documented way to draw an infinite horizontal line at a price. One `lineStyle` per `LineSegments` group, so group lines by colour/width. Emitting the group only on `d.isLast()` (and `graphics: false` otherwise) is what makes the previous candle's copy disappear. `op(a, '+', b)` is valid — `Op` is `"+" | "-" | "*" | "/" | "max" | "min"`.
- **Give any pane that mixes magnitudes an explicit `scaler`.** Autoscaling fits *every* field returned by `map`, so a price-valued series (EMA, VWAP ~22,000) carried alongside a volume series (~400) stretches the axis to the price and flattens the volume into the bottom pixel row. Restrict it with `scaler: { type: "multiPath", fields: [...] }`, naming only the fields that share a magnitude — see `scalpProMeter.js`. `displayOnly: true` on a plot stops it being *drawn*, but does **not** exclude it from autoscaling.

## TradingView ports (`trading-view/`)

Each Tradovate indicator except `signal.js` (Tradovate-only by request) and `bigTrades.js` (not ported yet) has a Pine Script v6 counterpart in `trading-view/<sameName>.pine`, pasted into TradingView's Pine Editor. Keep them behaviorally in sync when changing an indicator. Differences forced by Pine: ET sessions use the native `"America/New_York"` timezone (no hand-rolled DST); the HUD is a `table`; plots are static, so the ATR line count is fixed at 10; Market Magnet builds its profile from `request.security_lower_tf` intrabars (typical price × volume) since Pine has no `d.profile()`; Scalp-Pro VWAP uses `ta.vwap(hlc3)`; audio dings become `alertcondition`s.

## Existing indicators

- `indicators/scalpProMeter.js` — port of the ThinkorSwim "Scalp Pro Meter PSR" (Million-Dollar-Margin Club). Volume histogram + estimated buy/sell dots, each series joined by a line (`predef.plotters.singleline` on the same field, listed before the dots; `predef.plotters.line` does NOT exist and breaks module load) + a fixed HUD (strength meter, buy/sell %, EMA-vs-VWAP trend, volume-spike flag). HUD geometry is a `HUD_*` `CONFIG` block (rows derive from one `rowY(n)` helper, and the conditional TREND row reserves its slot so the VOL row never jumps); the pane carries an explicit `scaler` so the price-valued `ema`/`vwap` cannot stretch the volume axis. See `README.md` for the full feature mapping, the close-in-range buy/sell estimate, and how to swap in real delta via `d.offerVolume()/d.bidVolume()`.
- `indicators/atrLevels.js` ("ATR Levels"; formerly `nySessionAtrLevels.js`) — draws a center line at the **current candle's open** plus 5 ATR-spaced lines above and below, at all hours (not tied to any session). Re-anchors on every new candle and keeps exactly one ladder on the chart: the lines are infinite `LineSegments` graphics emitted only on `d.isLast()`, not plots (a plot's one-value-per-bar model would paint a staircase). Spacing is the ATR through the *previous* closed bar so the ladder does not twitch while the live candle forms. Cost of dropping plots: no legend entry and no UI colour picker — style via the CONFIG constants.
- `indicators/sessionRangeLevels.js` — eight horizontal levels marking the high/low of the Asia (18:00–03:00 ET), London (03:00–09:30), pre-market (04:00–09:30) and *previous* US (09:30–16:00) sessions, each with a short label (`ASH/ASL`, `LOH/LOL`, `PMH/PML`, `PDH/PDL`) at the right edge. Defines a **trading day that rolls at 18:00 ET** (not midnight) so Asia can span midnight and the just-closed US session becomes `PDH/PDL`; plots, styles and bool params are all derived from one `SESSIONS` config array. Labels are staggered into one horizontal column per session because price→pixel distance is unknowable at map time. Requires an ETH chart and bars ≤ 60m.
- `indicators/marketMagnet.js` — port of the ThinkorSwim "Market Magnet PSR" (Million-Dollar-Margin Club), which is really a session volume profile. Accumulates `d.profile()` (keyed by tick) inside three ET windows from the `WINDOWS` config — Asia first 2h (18:00–20:00), London first 2h (03:00–05:00), whole NY session (09:30–16:00) — with a fresh profile per window (keyed `id:dayKey`; windows may not cross midnight), then overlays the POC ("magnet", magenta) and the 50% value-area bands VAH/VAL (green/red dashed). Labels are prefixed with the active window name. Also draws per-bar arrow rows (green ▼ on VAH, red ▲ on VAL) and the profile itself as full-width translucent light-blue bars scaled by volume — all toggleable via top-of-file CONFIG. Carries its own ET/DST session helpers; falls back to typical-price×volume when a bar has no profile.
- `indicators/sessionCountdown.js` — graphics-only overlay (no plots) pinned bottom-left (`origin: { cs: "frame", h: "left", v: "bottom" }`, negative `y` offsets) showing, per session, either "OPEN" or the countdown to its next open. Sessions are the same ET futures windows as `sessionRangeLevels.js` (Asia 18:00–03:00 opening Sun–Thu, London 03:00–09:30, NY 09:30–16:00); users expect Asia to open with the Globex open at 18:00 ET, not the forex Tokyo open. Each `SESSIONS` entry has `tz` (`ny`/`london`/`tokyo`, hand-rolled DST), `open`/`close` (close ≤ open = overnight) and `openDays` (local weekdays it opens on). Uses `Date.now()` on the last bar (toggle `USE_WALL_CLOCK`). No holiday calendar.
- `indicators/signal.js` ("Signal (5m + 1m Scalp-Pro trend)") — buy "B" / sell "S" entries from the Scalp-Pro trend (EMA(14) vs session VWAP + EMA slope, same rule as `scalpProMeter.js`). A custom indicator only sees its chart's bars, so it runs **two candle pipelines side by side** and picks one at the last bar from the chart type: `mtf` on **1-min and tick/range charts** (bars grouped by the minute of their timestamp into 1-min candles, 5-min candles built from those) and `htf` on a **5-min chart** (the chart's bars are the 5-min candles; there is no 1-min data). Chart detection uses the GCD of all gaps between bar timestamps (time charts: exactly the period, weekends included; tick/range bars: ≤ 1 min even when Tradovate rounds their timestamps to the second or minute, and however slowly they form) plus "any bar not on a whole minute": ≤ 60s or off-minute → `mtf`, exactly 300s → `htf`, anything else → warning showing the detected spacing, no markers. Gaps come from the timestamps stored in the indicator’s own per-bar state, not `history.prior()`. Each pipeline keeps a forming candle in the per-bar state and, when a bar starts a new candle, judges the closed one (`judge()`) and stores it by candle number in `this.eng[mode].states` — keyed, so tick re-runs are idempotent. `mtf` rule: fires on the first 1-min candle of a new 5-min candle when the just-closed 5m candle and the 1m candle that closed with it agree, the forming 5m candle agrees (`requireLive5m`) and that 1m candle agrees while its WICK reaches the recent-range extreme (B: low in the bottom `zonePct`% of the last `rangeBars` 1-min candles; S: high in the top zone). `htf` rule: previous 5m candle (full rule) + this 5m candle + wick in zone. 5m trends always use the full rule; the entry candle drops the slope half unless `requireSlope` (default off) — requiring it made signals ~20x rarer (1.1 vs 22.2 per 1,000 random-walk bars). Wick, not close: a rising EMA needs close > EMA, which a bottom-zone close almost never satisfies. Markers are re-emitted from the last bar as `global: true` `Text` items at the x of the chart bar that made the candle's low (B, `centerBelow`) / high (S, `centerAbove`) — non-global `Polygon` arrows never rendered. HUD is exactly five rows by request: `5m closed`, `5m live`, `1m closed` (`n/a` on 5m), `range`, `LAST`. On a 1-min chart signals are identical to the earlier 1-min-only version (checked in the harness). No TradingView port.
- `indicators/bigTrades.js` ("Big Trades (bubbles) + Tape Speed") — green (buy) / red (sell) circles in two size tiers at prices where a bar's `d.profile()` `askVol`/`bidVol` crosses a threshold: a dark-shade dot for `mediumSize` ≤ size < `bigSize` (default 20–49) and a light-tint dot with a ring around it for size ≥ `bigSize` (default 50); falls back to bar-level `offerVolume()/bidVolume()` at the close. Indicators cannot see time & sales, so a bubble is one print only on a **1-tick chart**; elsewhere it is volume-at-price per bar. Tape speed = volume ÷ bar duration (gap to the next bar's timestamp; forming bar uses `Date.now()`), durations capped at `GAP_CAP` × median so session gaps don't skew it; `F` label above the bar when ≥ `speedMult` × the previous `speedBars` bars' average. Default `MARKER_STYLE = "plot"` draws the dots as **plots with `predef.plotters.dots`**: bar-anchored global graphics circles — `Shapes` + `Circle`, and the `Dots` display object — were both tried and did **not** render in Tradovate. **The dots plotter ignores the plot style's `lineWidth` — every dot is the same size** — so the tiers differ by colour (`TIERS` config) and big trades get an extra global `Text` mark from the last bar (`BIG_MARK`: `"ring"` = a bold ASCII `O` centred on the dot, `"size"` = the contract count beside it, `"none"`). A plot holds one value per bar, so `PLOT_DEFS` generates `SLOTS` (3) plots per tier × side (`buyBig1` … `sellMed3`) and a bar shows only its `SLOTS` largest trades per tier and side. `"text"` (trade size as global `Text` emitted from the last bar, font size per tier, every trade) is the alternative. HUD top-right is a single `TAPE` line by request (forming bar's speed vs the average, with ` F` when fast); the earlier `MED`/`BIG`/`SRC`/`MAX` diagnostic rows were removed. No TradingView port yet.
